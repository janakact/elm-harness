# v0.3 implementation

The v0.3 document supersedes the previous Rust-host plan. Elm owns the canonical backend model, agent state machine, context construction, prompt composition, tool definitions/validation, approval decisions, migrations and projections. Node performs transport, secret injection, physical storage, sandboxed tool execution and terminal I/O. The browser has only local view/input state and receives projections. Rust is removed.

Implemented:

- Elm backend worker and versioned action/event ports; browser and terminal Elm clients.
- Canonical immutable parent graph, forked threads, explicit captured deliveries and durable inboxes.
- OpenRouter streaming with fragmented tool-call assembly in Elm, correlation IDs, cancellation, sequential tool continuation and a configurable concurrency limit (default four).
- Exactly read/write/bash vocabulary, per-chat persisted allow/ask/deny policies, filtered schemas, argument checks, audited approvals, bounded output/time, containment and sensitive-path restrictions. Policies are decided in Elm and rechecked at execution by the host. Tool results/approvals are correlated to their chat/run. Linux bash uses Bubblewrap, fails closed if unavailable, hides the root .env and credential directories, has no network, and removes secrets from its environment. Denying write mounts the bash workspace read-only. Mutating tools are serialized.
- Elm prompt v3 with SYSTEM.md replacement, APPEND_SYSTEM.md additions and AGENTS.md project context. Each model call records effective prompt provenance as an activity.
- Persisted provider token/cost records by request/chat/model/purpose, a labelled local input estimate and configurable per-chat budget, plus the 25-tool-turn guard. Missing reported cost remains unknown/partial.
- Model-assisted compaction with no tools, editable previews, explicit acceptance against the captured source head, queued prompt/reference delivery, and preserved immutable history. Cancellation, failure and restart never silently accept a summary. User-supplied `/compact SUMMARY` remains available.
- Separate core/user schemas, additive user migration, invalid-version rejection, graph checks, atomic serialized saves/backups and interrupted-tool recovery without automatic replay.
- Fixed viewport browser shell with scrolling chat, anchored composer, responsive sidebar, graph/detail panel, approvals, model settings, run/stop, branching and reference delivery.
- Composer autofocus, separate drafts per chat, and a read-only modal JSON state explorer with expand/collapse/search, refresh and copy.
- Elm Markdown/math tokenization, safe Markdown, tables, highlighted copyable code, local KaTeX leaf adapter, and terminal LaTeX fallback.
- Full-screen Elm TUI with responsive chat/history panes, fixed editable composer, message inspection, scrolling, safe paste, permission review, keyboard shortcuts, and backend auto-start/cleanup. Terminal host handles raw keys, resize, ANSI writes and transport; Elm owns all interaction and layout semantics.

Verification: npm test covers the actual compiled Elm worker and terminal, complete tool loop, per-chat policies, reused tool-call IDs, usage, input guards, summary review/cancellation/recovery, approvals, cancellation, inbox recovery, namespace migration, concurrent scheduling, containment and atomic storage. Browser fixtures check navigation/focus, state exploration, workspaces, permissions, usage, compaction and the fork/reference controls. The session fixture uses a local provider stub. A rich-content fixture checks Markdown/math/code and fixed viewport at desktop/mobile sizes. An earlier live DeepSeek V4 Flash request read package.json through the real host and completed its answer.

Implemented scope: three native coding tools and read-only Codex/Claude jobs; no isolated runner writes, distributed hosting or dynamic plugin loading yet. Shell execution requires Linux Bubblewrap. Parallel mutations are serialized; forks still share the source workspace. All policy, accounting, compaction and UI state semantics remain in Elm; Node remains the I/O adapter.

Updated direction (12 November): the user has requested typed state/view plugins, additional backends and Codex/Claude-style runners. The bounded cleanup/readiness milestone and read-only external runners in [PLUGIN_RUNNER_DESIGN.md](PLUGIN_RUNNER_DESIGN.md) are implemented. Next add isolated write workspaces and delegated task workflows. The design distinguishes our canonical Elm application state from each external agent's internal loop; external job state and protocol semantics are in Elm; Node provides process I/O.

Foundation cleanup (12 November): clients now depend on App.Public instead of the persistence decoder; run statuses are typed; Agent.Context/Message and Providers.OpenRouter separate native history from provider DTOs. Model/tool effects wait for durable-save acknowledgement. The existing User module is a typed state/view plugin using shared Ui slots and public actions; unsupported plugin data is quarantined and preserved. The subsequent runner increment implements typed Codex/Claude jobs, durable launch intents, explicit session resume, read-only mounts, cancellation, reporting, capability probes and web/TUI controls. Worktree writes and delegated tasks remain next.

Runner validation: compiled Elm worker/TUI tests cover session ownership, old/duplicate events, queue limits, cancellation, persistence failure and restart without replay. Real fixture child processes cover partial UTF-8/JSONL, read-only mounts, secret masking, nonzero exits, malformed output, timeout and byte limits. A browser fixture covers both backends, reporting, explicit resume, cancellation, reload and mobile modal focus.
